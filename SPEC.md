# CodeLingo — ТЗ

> Восстановлено по фактическому поведению версии 1.0.x (2026-11-08). Новые требования дописываются сюда до начала работы над фичей.

## Что это
Офлайн-тренажёр программирования для джунов в стиле 8-bit: короткие уроки из заданий по HTML, CSS, JavaScript, TypeScript, Python и SQL. Без сервера, без аккаунтов, весь прогресс хранится на устройстве.

## Платформы
| Платформа | Как запускается | Минимум |
|---|---|---|
| iPhone / iPad | Safari → «На экран Домой» (PWA) | iOS 15.4+ (оценка по используемым API; на реальном устройстве не проверялось) |
| Android | Chrome → «Установить приложение» (PWA) или APK/AAB через PWABuilder (TWA) | Android 9+, Chrome 109+ |
| Компьютер | Любой современный браузер; `dist/codelingo.html` открывается из файла | Chrome/Edge/Firefox/Safari последних 2 версий |

Ширина экрана от 320 px (iPhone SE) до планшетов и компьютера. Основная ориентация — портретная (manifest), но iOS её не фиксирует, поэтому альбомная тоже должна выглядеть корректно.

## Общие требования
- R1. Работает офлайн после первого запуска по https (service worker, cache-first). Каждое изменение файлов поднимает `VERSION` (app.js) и `CACHE` (sw.js) вместе.
- R2. Языки интерфейса и заданий: en, ru, uk, cs. Язык по умолчанию — язык системы, иначе en.
- R3. Темы: Авто / Светлая / Тёмная; `theme-color` обновляется вместе с темой.
- R4. Зона нажатия ≥ 44×44 px; нет горизонтальной прокрутки на 320 px; учтены safe area (вырез, home indicator).
- R5. Прогресс в `localStorage` (ключ `codelingo.v1`). Повреждённые или чужие данные при загрузке не ломают запуск (sanitize).
- R7. Раскладка (проверяет `tools/layout-check.py` на матрице: iPhone SE 1 320×568 … Pro Max 430×932, Android 360×800, iPhone в альбомной 852×393, iPad mini 744, iPad 820, десктоп 1280):
  - нет переполнения, обрезанного текста и наложения элементов;
  - кнопки и поля не заходят под вырез, home indicator и боковые вырезы в альбомной ориентации;
  - контент не прячется под панелью вкладок и футером урока;
  - панель вкладок выровнена по колонке контента (на широких экранах не растягивается на всю ширину);
  - от 700 px ширины — планшетная раскладка: колонка контента шире, курсы в 3 колонки; урок остаётся узкой колонкой для чтения;
  - подсказка маскота не закрывает текст вопроса и варианты ответа.
- R8. Каркас приложения: документ не прокручивается; каркас прижат к краям экрана (`position: fixed; inset: 0`) без единиц `vh`/`dvh` (в iOS standalone с `viewport-fit=cover` они при запуске считаются без статус-бара и дают полосу под панелью вкладок; тот же принцип для экрана урока), прокручивается только область контента. Панель вкладок всегда прижата к нижнему краю экрана (с отступом под home indicator) и не сдвигается при переключении вкладок и при любой длине контента. Смена вкладки или экрана открывает новый экран с начала, без прыжков.
- R9. Типографика, минимализм: один системный шрифт для всего интерфейса; моноширинный — только внутри кода (блоки кода, поля ввода кода, блоки сборки, варианты-код). Варианты ответа без символов кода и с пробелом (например «HyperText Markup Language») — обычным шрифтом. Три размера: заголовок 22 px, текст 17 px, подпись 13 px; код — фиксированно 15 px (поля ввода — не меньше 16 px). Насыщенность только 400 и 600. Одна и та же роль текста выглядит одинаково на всех экранах. Обычный регистр без разрядки; КАПС — только у главной кнопки урока («Проверить» / «Далее»). Числа в интерфейсе — только процент курса (экран курса и профиль) и статистика курсов в профиле (экран 4); на остальных экранах чисел нет.
- R6. Поля ввода кода: шрифт ≥ 16 px (без зума в iOS), без автокоррекции; «умные» кавычки iOS нормализуются при проверке.
- R10. Геометрия: сетка 8 px. Поля экрана 16 px, промежуток между карточками 16 px, внутренний отступ карточек 16 px, между секциями 24 px. Колонка контента и панель вкладок отцентрированы и одной ширины. Текст в кнопках и карточках курсов центрирован. Одна тень (3 px 3 px 0) у всех интерактивных карточек и кнопок, у статичного текста теней нет. На экранах нет пустых полос: сетка курсов заполняет высоту области контента.
- R12. Никакого системного UI устройства (решение владельца 2026-11-09): нет `window.confirm`/`alert`/`prompt`, выбора файлов и системного «Поделиться». Подтверждения (выход из урока, сброс прогресса) — модальное окно в стиле приложения: заголовок, две кнопки («Отмена» и действие), фокус внутри окна, Esc и тап по фону = отмена. На элементах интерфейса нет системных меню долгого нажатия, лупы выделения и подсветки тапа (`-webkit-touch-callout: none`, `user-select: none`, `-webkit-tap-highlight-color: transparent`); блоки кода можно выделять.
- R11. Музыка: тихая зацикленная собственная 8-битная мелодия (WebAudio, без файлов), играет только пока открыт урок; останавливается при выходе, на экране итога и при сворачивании приложения (`visibilitychange`). Запускается от нажатия (требование iOS). Громкость низкая, без резких высоких нот. Включается и выключается в настройках, по умолчанию включена.

## Информационная архитектура
Решение владельца (2026-11-08): минимум кнопок и текста. Из предложения по образцу mate.academy взяты только три вкладки и статусы уроков. Карточка «Продолжить», дневная цель и сертификаты не делаются.
- IA1. Вкладок три, порядок: Учиться, Профиль, Настройки. Переключение вкладок не меняет высоту и положение панели вкладок и шапки.
- IA2. На экране курса статусы уроков: пройден (пиксельная галочка) / следующий (акцент, «Начать») / закрыт (приглушённый замок).
- IA3. Полностью пройденный курс отмечен на своей плитке маленькой пиксельной галочкой.

## Экраны

### 1. «Учиться» — список курсов
- 6 одинаковых карточек курсов в сетке 2×3 (от 700 px — 3 колонки); ряды заполняют высоту области контента. В карточке по центру — тег и название; без подзаголовка экрана, чисел и полос.
- Нажатие открывает экран курса.

### 2. Экран курса
- Шапка: тег, название курса и процент знаний k% — процент тем же шрифтом, размером и насыщенностью, что и название.
- 10 уроков одинаковой высоты. Открыт первый урок и каждый следующий после пройденного; закрытые недоступны.
- Кнопка «Назад» возвращает к списку курсов.

### 3. Урок
- 8 заданий четырёх типов: выбор варианта, заполнение пропуска, написание кода, сборка кода из блоков (в части заданий — с лишними блоками).
- Кнопка «Проверить» активна, только когда есть ответ; защищена от двойного нажатия (ответ не засчитывается дважды, быстрый второй тап не пропускает экран с ответом).
- Неверный ответ показывает только «Неверно» — правильный ответ не раскрывается (решение владельца 2026-11-09); задание возвращается в конец очереди, чтобы попробовать ещё раз.
- Проверка ответа не интерпретирует `$`-шаблоны во введённом тексте (ввод `$${` не равен `${`).
- XP за задание: 10 — с первой попытки без подсказок, 5 — с подсказкой, 2 — после ошибки.
- Маскот-подсказка: убирает неверный вариант / показывает начало ответа / подсвечивает следующий блок / сообщает, что среди выбранных блоков есть неверный. Отключается в настройках.
- Панель символов над клавиатурой (`{ } < > ;` и т. п.): тап вставляет символ в позицию курсора, не закрывая клавиатуру; свайп по панели ничего не вставляет.
- Выход из урока после первого ответа — с подтверждением (до первого ответа — без вопроса). Незавершённый урок не отмечается пройденным и не даёт XP; данные ответов при этом уже учтены в точности (см. «Открытые вопросы»).
- По завершении урока сохраняется лучшая точность урока: `prog[id].best[номер_урока]` = максимум из старого и нового значения 0–100 (проходит sanitize).
- Во время урока играет музыка (R11).
- Экран итога: маскот и «Урок пройден!» без чисел.

### 4. Профиль
- Отметки за последние 7 дней (без подписи-заголовка).
- По каждому курсу — отдельный блок-карточка (без тени: статичный блок, не кнопка), между блоками 16 px. Статистика видна сразу во вкладке, без дополнительных нажатий (решение 2026-11-09: эргономичнее, чем кнопка «Статистика» у каждого курса).
  - Строка 1: тег (плашка) и название курса слева, процент знаний k% справа — как в шапке экрана курса (те же элементы и стиль). Процент в формате языка (cs — «45 %», en/ru/uk — «45%»), для screen reader — «Знания: 45%».
  - Строка 2: полоса из 10 равных сегментов, по одному на урок (для screen reader скрыта: подпись говорит то же). Не пройден — пустой сегмент; пройден — цвет по лучшей точности урока: ≥ 90 % зелёный, ≥ 60 % жёлтый, < 60 % красный.
  - Строка 3 (подпись 13 px): всегда две строки, выровненные влево, — «Пройдено уроков: N из 10» и «Верных ответов P% (ok из ans)». Если ответов ещё не было — «Верных ответов —». Высота всех блоков одинакова.
  - Без слов-уровней.
- Процент знаний курса k = `уроки_пройдено/всего × (0.5 + 0.5 × точность)`.

### 5. Настройки
- Тема — одна кнопка с текущим значением; нажатие переключает по кругу Авто → Светлая → Тёмная.
- Язык — одна кнопка с названием языка; нажатие переключает по кругу English → Русский → Українська → Čeština.
- Переключатели: звуки, музыка, подсказки маскота, анимации.
- Сброс прогресса с подтверждением.
- Версия приложения.
- Размер кода, дневная цель, экспорт и импорт прогресса убраны (решение владельца 2026-11-08: вернутся по мере развития).

## Решения по реализации (2026-11-09)
Приняты в цикле builder/tester/reviewer; владелец их ещё не подтверждал.
- D1. Номер версии в настройках («CodeLingo · X.Y.Z») — допустимое исключение из правила о числах (R9).
- D2. Пройденный урок без сохранённой лучшей точности (пройден до версии 1.0.6) окрашивается в профиле по общей точности курса.
- D3. Строки уроков на экране курса: название слева, статус справа (шаблон списка) — исключение из центрирования текста R10.
- D4. Если iOS не даёт возобновить музыку после возврата из фона, она возобновляется при следующем нажатии в уроке.

## Вне рамок
Аккаунты, синхронизация между устройствами, сервер, реклама, покупки, push-уведомления, выполнение настоящего кода (Pyodide/sql.js).

## Открытые вопросы
1. Публикация в App Store: нужен Apple Developer ($99/год) и Xcode; на этом Mac (macOS 13.2) свежий Xcode не ставится. Делаем только PWA для iOS? (сейчас — да)
2. Иконка 512 px помечена `any maskable`. На Android маскирующая обрезка может срезать края пиксель-арта; нужна отдельная maskable-иконка с полями ≥ 10%?
3. Публикация в Google Play через TWA (PWABuilder) нужна, или достаточно установки PWA из Chrome?
4. Прогресс живёт только на устройстве и пропадает при удалении иконки с iOS — это допустимо?
5. Ответы из брошенного урока сейчас учитываются в точности и проценте знаний. Учитывать только завершённые уроки?
6. Аппаратная/жестовая «Назад» на Android в установленной PWA/TWA закрывает приложение (нет обработки history). Нужно: урок → подтверждение выхода, курс → список курсов?
7. Лишние блоки есть только в 1 задании на сборку из 50. Добавить их в остальные задания?
8. При неудачном скачивании в standalone-режиме iOS (если меню «Поделиться» недоступно) пользователь не получает обратной связи. Нужен toast или текст JSON для копирования?
